## 1. 这是什么

一个跑在云服务器上的**豆粕数据看板**：每天自动抓公开行情，生成一个静态页面，供盘前判断使用。

- 访问地址：**https://data.windxiao.site/**
- 登录方式：HTTP Basic Auth，用户名 `maxiao`（密码由机主掌握，不在本文档里）
- 展示：盘前一页纸（四维仪表盘 + 行情 + 价差 + 数据录入表单）

## 3. 项目在服务器上的位置

```
/srv/mp-data/
├── app/            # 代码（零第三方依赖，纯标准库）
├── db/mp.sqlite3   # SQLite 数据库
├── raw/            # 每次抓取的原始响应留档
├── site/           # 生成的静态页（nginx root）
├── logs/           # fetch.log / api.log
├── backup/         # 每日数据库备份，保留 30 份
└── deploy/         # systemd 单元
```

专用用户 `mpdata` 跑所有任务；`/srv/mp-data` 目录权限 755，`site/` 对 nginx 只读。

### 三个 systemd 服务

| 单元 | 作用 | 时间 |
|---|---|---|
| `mp-data.timer` → `mp-data.service` | 抓行情 + 重生成页面 | 每天 08:35、15:10、**17:30** |
| `mp-data-news.timer` → `mp-data-news.service` | 只抓快讯，命中关键词即推送 | 08:00–23:00 每 30 分钟 |
| `mp-data-brief.timer` → `mp-data-brief.service` | 抓隔夜资讯 + AI 简报 + 发邮件 | 每天 **07:30** |
| `mp-data-backup.timer` → `mp-data-backup.service` | 备份数据库 | 每天 03:20 |
| `mp-data-api.service` | 网页录入写入接口 | 常驻，`127.0.0.1:8765` |

> **为什么是 17:30 而不是 21:00**：夜盘 21:00 开的属于**下一个交易日**，那时抓到的
> 是「新交易日 + 结算价 0」。交易所结算价通常 15:30~16:30 才发布，所以兜底必须落在
> 15:30 之后、21:00 之前。
>
> **两道防护**：
> 1. `fetch.py` 跳过结算价为 0 的记录（否则基差 = 现货 − 0，结构维度方向直接算反）；
> 2. `repair_recent_settles()` 每次运行都从日线接口核对近 6 天结算价并补齐，
>    即使某次没抓到，第二天早上也一定会补回来。

| 页面 | 说明 |
|---|---|
| `index.html` | 盘前看板：结论 + 四维卡片 + 行情/价差 + 资讯/日历 + 折叠体检 |
| `input.html` | 数据录入（7 项），保存后自动重生成看板 |
| `weekly.html` | 10 个序列的历史表 |
| `brief.html` | 豆粕简报列表（按日期倒序），点日期看当天 |
| `brief/YYYY-MM-DD.html` | 豆粕简报：AI 导语 + 昨日数据 + 快讯 + 日历 |
| `macro.html` | 全局简报列表 |
| `macro/YYYY-MM-DD.html` | 全局简报：AI 概览 + 八板块要闻 + 汇率 |

> **Server酱 只发系统故障**（免费额度 5 条/天）。简报、快讯、体检异常一律只发邮件，
> 代码里用 `notify.send(..., channels=("mail",))` 显式限定。
>
> 简报的 AI 摘要凭据在 `/etc/mp-data/llm.json`（600 权限），
> 格式 `{"api_key":"sk-...","base_url":"...","model":"deepseek-chat"}`。
> 接口失败会自动降级为规则结论，简报不会缺。

> ⚠️ **改完 `render.py` 要执行 `systemctl restart mp-data-api.service`**，
> 否则常驻的接口进程仍用旧代码渲染，会把页面覆盖回旧版。

常用命令：

```bash
systemctl list-timers "mp-data*" --no-pager
journalctl -u mp-data.service -n 50 --no-pager
tail -f /srv/mp-data/logs/fetch.log
systemctl restart mp-data-api.service

# 告警
sudo -u mpdata python3 /srv/mp-data/app/notify.py   # 发测试邮件
sudo -u mpdata python3 /srv/mp-data/app/health.py   # 手动体检
```

### 告警配置

凭据在 `/etc/mp-data/notify.json`（权限 600，属主 mpdata，**不进 git**），
结构见 `mp-data/README.md` 的「告警」一节。QQ 邮箱需要用 **SMTP 授权码**，不是登录密码。

金十数据 Token 在 `/etc/mp-data/jin10.json`（同样 600），格式 `{"token": "..."}`，
可在 https://mcp.jin10.com/app/ 重置。

当前启用两个通道，同时发送、互不依赖：

| 通道 | 说明 |
|---|---|
| 邮件 | QQ 邮箱 SMTP |
| Server酱 | 微信「方糖」服务号，SendKey 以 `SCT` 开头 |

告警规则：任务异常 / 序列超期（现货 >4 天、库存等 >12 天）/ 非正结算价 / 基差 >400。
同一组问题 12 小时内只发一次。

> 两个 SendKey/授权码都曾出现在对话记录里。若要换：QQ 邮箱重新生成授权码，
> Server酱在 sct.ftqq.com 重置 SendKey，然后改 `notify.json` 并跑一次
> `sudo -u mpdata python3 /srv/mp-data/app/notify.py` 验证。

## 6. 新电脑接入步骤

### 6.1 准备项目文件

把 `豆粕项目交接包.zip` 解压到新电脑的某个目录，例如 `D:\DSH\豆粕\`。

包内：`mp-data/` 源码 + `数据源设计.md` + `部署方案.md` + `豆粕期货专注交易研究手册.md`。

> 服务器上已有完整代码，本地这份主要用于阅读和修改。改完用 `scp` 推上去即可。

### 6.2 配置 SSH 密钥

**推荐：在新电脑上生成新密钥**（不要把私钥复制来复制去）。

PowerShell 里执行：

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\mp_data"
```

⚠️ **提示 passphrase 时直接回车**（不要输任何内容）。
Windows 下用 `-N ""` 有坑，可能把空字符串当成口令写进去，导致之后每次都要输密码。

然后查看公钥：

```powershell
type "$env:USERPROFILE\.ssh\mp_data.pub"
```

### 6.3 把公钥加到服务器

SSH 还没通，所以这一步要在**腾讯云控制台的 VNC 登录**里做：

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '把上面输出的公钥整行粘在这里' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### 6.4 验证

```powershell
ssh -i "$env:USERPROFILE\.ssh\mp_data" -o ConnectTimeout=15 <用户名>@<服务器IP> "hostname; systemctl is-active mp-data-api.service"
```

能打印主机名和 `active` 就成功了。

## 8. 故障排查：SSH 连不上

### 8.1 先判断是哪一侧的问题

**症状**：`ssh` 卡在 `Connection timed out during banner exchange`。

用下面这段 Python 判断（HTTP 能过、SSH 不能过，就说明是网络拦截）：

```python
import socket
def probe(host, port, payload, wait=12):
    s = socket.create_connection((host, port), timeout=10)
    s.settimeout(wait)
    s.sendall(payload)
    try:
        print(host, port, '->', s.recv(60))
    except Exception as e:
        print(host, port, '-> NO RESPONSE', type(e).__name__)
    s.close()

probe('<服务器IP>', 22, b'HEAD / HTTP/1.0\r\n\r\n')   # 能收到 SSH banner
probe('<服务器IP>', 22, b'SSH-2.0-probe\r\n')        # 大概率无响应
```

**结论规则**：

- 发 HTTP 能收到 banner、发 SSH 版本串收不到 → **本地网络做了协议级拦截**
- 两个都收不到 → 服务器或安全组问题

### 8.2 已知现象

2026-11-17 换到某个 Wi-Fi 后出现过：TCP 能连、SSH banner 收不到；同网络下 github.com:22 也一样失败。判定为**该网络只放行 HTTP/HTTPS**，与服务器无关。

服务器当时状态：PID 1 正常（`Ss`）、无卡住任务、`ssh.socket`/`ssh` 都 active、sshd 能正常吐 banner。

### 8.3 绕行方案（未实施）

把 SSH 包进 TLS 传输（因为 TLS 被放行）：

1. 服务器开一个 TLS 端口（如 8443）转发到 `127.0.0.1:22`
2. 腾讯云安全组放行 8443
3. 本地写一个 TCP 中继，把 SSH 流量套进 TLS 再发出去

未实施原因：换回原网络后 SSH 恢复，且当时无法远程操作服务器。

### 8.4 服务器上有个已知小毛病

每次 SSH 登录会卡 25 秒并打日志：

```
pam_systemd(sshd:session): Failed to create session:
Failed to activate service 'org.freedesktop.login1': timed out (25000ms)
```

## 9. 安全提醒

- 站点有 basic auth，但**不要在公网页面放持仓、止损位等私密信息**
- 写入接口只监听 `127.0.0.1`，只能经 nginx 访问，不要改成 `0.0.0.0`
- SSH 私钥无口令，**不要提交到任何 git 仓库**
- 服务器 `ufw` 处于关闭状态，全靠腾讯云安全组防护；Halo 的 8090 绑在 `0.0.0.0`（公网测过连不上，大概率被安全组挡了，但仍建议确认）

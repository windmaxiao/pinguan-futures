# 豆粕数据平台 · 部署方案（v0.1 草案）

> **文档状态**：本文是 v0.1 设计草案，部分内容是当时的推演，实现后有出入。
> 现行实现以 mp-data/README.md 和 mp-data/app/config.json 为准；
> 本文保留作设计思路的存档，**改动会就地标注「2026-11 更新」**。

> 配套文档：`数据源设计.md`（抓什么、怎么算、怎么展示）
> 场景：已有云服务器 + 博客站点，希望「抓数据 + 展示页面」都跑在服务器上，博客里加个链接点进去看。

---

## 0. 一句话结论

**展示用静态页，只有录入需要一个极小的写接口。**

主链路仍然是「**定时脚本抓取 → 生成静态页面 → Nginx 直接托管**」：

- 页面是静态文件，没有进程挂掉、内存泄漏、端口冲突的问题；
- 服务器重启后，Nginx 起来页面就在；
- 页面天然只读，只能看不能改。

> **v0.2 起新增**：网页上要能填数据，静态文件做不到，所以加了一个只监听
> `127.0.0.1:8765` 的写接口（`mp-data-api.service`），由 Nginx 反代 + 访问码门禁（`auth_request`）。
> 它不对外暴露、只接受 JSON POST、指标和数值都要过白名单校验，攻击面仍是「只有 nginx 443」。

## 1. 整体架构

```
                 ┌──────────────── 云服务器 ────────────────┐
                 │                                          │
  浏览器 ──HTTPS──▶ Nginx :443                                │
                 │   ├── blog.example.com  ──proxy──▶ 博客服务 :8090（现有，不动）
                 │   └── data.example.com  ──root───▶ /srv/mp-data/site/（静态）
                 │                                          │
                 │   systemd timer  08:35 / 15:10            │
                 │        │                                 │
                 │        ▼                                 │
                 │   抓取脚本（Python venv，只出站不监听）      │
                 │        ├──▶ 大商所 / USDA / 生意社 ...     │
                 │        ├──▶ SQLite  /srv/mp-data/db/       │
                 │        ├──▶ 原始快照 /srv/mp-data/raw/     │
                 │        └──▶ 生成页面 /srv/mp-data/site/    │
                 └──────────────────────────────────────────┘
```

要点：
- **抓取脚本不监听任何端口**，只做出站请求、只写文件。它永远不对外暴露。
- 展示页是**静态文件**，Nginx 直接读，跟博客完全解耦。
- 博客一个字节都不用改，只在后台菜单里加一条外链。

## 2. 目录结构

```
/srv/mp-data/
├── app/                    # 代码（git clone 或上传）
│   ├── fetch.py            # 抓取入口
│   ├── render.py           # 生成页面
│   ├── indicators.yaml     # 指标注册表（编号、单位、来源优先级）
│   └── config.yaml         # 阈值、口径、地区、费用系数
├── venv/                   # Python 虚拟环境
├── db/mp.sqlite3           # 主数据库
├── raw/                    # 原始快照，YYYY-MM-DD/<source>-<ts>.json
├── site/                   # ★ Nginx 只读根目录
│   ├── index.html          # 盘前一页纸
│   ├── weekly.html
│   ├── data/*.json         # 图表数据
│   └── assets/
├── logs/
│   ├── fetch.log
│   └── render.log
└── backup/                 # 数据库每日备份，保留 30 天
```

权限：
- 代码与数据属主 `mpdata:mpdata`（专用系统用户，`nologin`）。
- `site/` 对 `www-data`（或 Nginx 运行用户）只读。
- 抓取脚本以 `mpdata` 运行，**不用 root**。

## 3. 与现有博客共存的两种接法

### 方案 A：子域名（推荐）

`data.example.com` → 独立的 Nginx server 块 → 指向 `/srv/mp-data/site/`。

优点：与博客零冲突、可独立加密码、可独立限流、以后想换实现不影响博客。
代价：要在 DNS 加一条 A 记录（5 分钟的事）。

### 方案 B：同域名子路径

在现有博客站点的 server 块里插一段：

```nginx
location ^~ /mp-data/ {
    alias /srv/mp-data/site/;
    index index.html;
    try_files $uri $uri/ /mp-data/index.html;
}
```

优点：不用改 DNS，链接短。
代价：`alias` 与博客的 SPA 路由容易打架，博客升级时有人改配置可能把它弄丢；且 `/mp-data/` 会暴露在主站下。

**建议：A。** 除非你没有域名或不能改 DNS。

## 4. Nginx 配置（方案 A，可直接抄）

```nginx
# HTTP 跳 HTTPS
server {
    listen 80;
    server_name data.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;                      # nginx < 1.25.1 请改成 listen 443 ssl http2;
    server_name data.example.com;

    ssl_certificate     /etc/letsencrypt/live/data.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/data.example.com/privkey.pem;

    root  /srv/mp-data/site;
    index index.html;

    # ⚠️ 2026-11 更新：已从 basic auth 改为「访问码门禁」，
    # 完整可用的配置见 mp-data/deploy/nginx-data.conf（含 auth_request、解锁页放行等）。
    # 下面这段 basic auth 仅作历史参考，照抄会与后端门禁冲突。
    # auth_basic           "MP Data";
    # auth_basic_user_file /etc/nginx/.htpasswd;

    add_header X-Robots-Tag "noindex, nofollow" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Cache-Control "no-cache" always;   # 每天更新，别让浏览器缓存旧页

    location /api/ {
        client_max_body_size 4k;
        proxy_pass http://127.0.0.1:8765;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30;
    }

    location / {
        try_files $uri $uri/ =404;
    }
}
```

配套命令（Ubuntu/Debian 系）：

```bash
sudo apt install -y apache2-utils certbot python3-certbot-nginx
sudo htpasswd -c /etc/nginx/.htpasswd mpdata     # 只提示输入密码
sudo certbot --nginx -d data.example.com
sudo nginx -t && sudo systemctl reload nginx
```

> 1Panel / 宝塔用户：不要手改 `/etc/nginx/conf.d`，在面板「网站 → 反向代理/静态站点」里建站点，再贴上述 `auth_basic` 和 `add_header` 部分，否则面板重写配置时会覆盖掉。

## 5. 在博客里加链接

以常见博客后台为例：

1. 后台 → **外观 → 菜单**
2. **新增菜单项**
3. 类型选 **自定义链接**
4. 名称：`豆粕数据`；地址：`https://data.example.com/`
5. 打开方式选 **新窗口**
6. 保存 → 前台右上角菜单即出现

补充：
- 也可以在一篇文章里直接写 Markdown 链接：[豆粕数据看板](https://data.example.com/)
- **不建议用 iframe 嵌进博客页面**：多数博客默认带 `X-Frame-Options`，且两个域名跨域会有样式、高度、鉴权弹出框一堆问题，外链新窗口体验更好。
- 现在用的是访问码门禁：首次访问显示解锁页，输入访问码后 7 天免输（cookie）。

## 6. 定时任务（systemd timer，比 cron 好排查）

`/etc/systemd/system/mp-data.service`

```ini
[Unit]
Description=豆粕数据抓取与页面生成
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
User=mpdata
Group=mpdata
WorkingDirectory=/srv/mp-data
Environment=TZ=Asia/Shanghai
Environment=PYTHONUNBUFFERED=1
ExecStart=/srv/mp-data/venv/bin/python /srv/mp-data/app/fetch.py
ExecStartPost=/srv/mp-data/venv/bin/python /srv/mp-data/app/render.py
StandardOutput=append:/srv/mp-data/logs/fetch.log
StandardError=append:/srv/mp-data/logs/fetch.log
TimeoutStartSec=600
```

`/etc/systemd/system/mp-data.timer`

```ini
[Unit]
Description=豆粕数据定时任务

[Timer]
OnCalendar=*-*-* 08:35:00      # 盘前（含昨夜美豆收盘）
OnCalendar=*-*-* 15:10:00      # 日盘收盘后
Persistent=true                 # 服务器重启/关机错过则补跑
Unit=mp-data.service

[Install]
WantedBy=timers.target
```

启用与查看：

> **2026-11 更新**：现在一共 6 个定时器，`install.sh` 全部装好并启用。
> 上例只是最初的抓取任务，完整清单：
>
> | 定时器 | 时间 | 作用 |
> |---|---|---|
> | `mp-data.timer` | 08:35 / 15:10 / 17:30 | 行情抓取 + 渲染 + 体检 |
> | `mp-data-backup.timer` | 03:20 | 数据库备份（保留 30 份）|
> | `mp-data-brief.timer` | 07:30 | 生成两份简报并发邮件 |
> | `mp-data-news.timer` | 08:00–22:30 每 30 分钟 | 金十快讯采集 |
> | `mp-data-mysteel.timer` | 18:30 | Mysteel 产业数据采集与同步 |
> | `mp-data-wasde.timer` | 08:10 | USDA WASDE 检查（月度更新）|
>
> 另外 `mp-data-api.service` 常驻监听 `127.0.0.1:8765`，供网页录入与门禁校验。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mp-data.timer
systemctl list-timers mp-data.timer     # 看下次执行时间
journalctl -u mp-data.service -n 50     # 看最近一次跑的结果
tail -f /srv/mp-data/logs/fetch.log
```

**时间点为什么是这两个：**
- 08:35：拿到昨夜 CBOT 收盘（北京时间 02:20/03:20 收），赶在 09:00 开盘前生成；
- 15:10：日盘收盘后刷新当日结算价、持仓、基差。
- WASDE 发布日（通常北京时间凌晨）由 08:35 那次自动带上，不用单独排。

## 7. 运行环境

**v0.1 零第三方依赖**（纯 Python 标准库），所以不需要 venv、不需要 pip install：

```bash
# 只需要系统自带的 python3（3.8+）
sudo apt install -y python3        # 多数发行版已自带
python3 --version
```

如果以后接入更多数据源（如 AkShare），再补 venv 与 `requirements.txt`，并把版本钉死——AkShare 上游接口改得频繁，裸装会突然全挂。

**服务器位置的影响：**

| 服务器位置 | 新浪行情 | USDA | 备注 |
|---|---|---|---|
| 境内（当前） | 快 | 慢但可用 | 已确认 |
| 境外 | 慢/偶发超时 | 快 | 抓取要加长超时 + 重试 |

**时区**：服务器系统时区无所谓，`systemd` 里显式 `TZ=Asia/Shanghai` 即可；但**数据库日期一律存北京时间**，否则美豆和连粕会对错日期。

## 8. 安全与运维

| 项 | 做法 |
|---|---|
| 对外暴露面 | 只有 Nginx 443；抓取脚本不监听端口 |
| 访问控制 | 访问码门禁（HMAC 签名 cookie，访问码 7 天 / 管理码 1 天）；详见 mp-data/README.md |
| 搜索引擎 | `X-Robots-Tag: noindex` |
| 数据不外泄 | 持仓、止损位等私密数据**放本地，不上公网页面** |
| 备份 | 每日 `sqlite3 .backup` 到 `backup/`，保留 30 天；可选同步到对象存储 |
| 日志轮转 | 配 `logrotate`，避免 fetch.log 无限增长 |
| 失败告警 | 可选：失败时向你的邮箱/Server 酱/Telegram 发一条；第一版先用页面红条 + 日志 |
| 依赖更新 | 每季度手动升一次 AkShare，先在测试目录跑通再切 |

## 9. 怎么交付到你的服务器

已确认走 **SSH 直连**（不装 agent）：

1. 你在服务器上放好 SSH 公钥（见 §11 的一次性配置）；
2. 我通过本机 `ssh` 直接：上传代码 → 执行 `install.sh` → 配 Nginx → 验证页面；
3. 之后改代码、改口径、看日志，都由我直接操作，不再需要你手工上传。

一次性配置（你在 Windows 上执行，只需一次）：

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\mp_data -N '""'
# 把公钥内容追加到服务器的 ~/.ssh/authorized_keys
type $env:USERPROFILE\.ssh\mp_data.pub
```

然后在服务器上（或用密码 `ssh-copy-id`）：

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo "<粘贴公钥内容>" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

最后验证（在 Windows 上）：

```powershell
ssh -i $env:USERPROFILE\.ssh\mp_data <用户>@<服务器IP> "echo ok"
```

打印 `ok` 就说明我能接管后续部署。

> 如果你不想开放 SSH，退化方案仍可用：我生成 `mp-data.tar.gz`，你在 1Panel/宝塔上传解压后手工跑 `install.sh`。

## 10. 已确认与待补充

| 项 | 结论 |
|---|---|
| 博客 | **Docker 部署**，接口不动，只在后台菜单加外链 |
| 反向代理 | **Nginx** |
| 服务器 | **境内** |
| 访问控制 | **访问码门禁**（HMAC 签名 cookie）|
| 调度 | **systemd timer**（不用 agent） |
| 部署通道 | **SSH 直连** |
| 域名 | `example.com`；数据站用 `data.example.com` |

**还差两项：**

1. **DNS**：在 `example.com` 的解析里加一条 `A` 记录，主机记录 `data`，值 = 服务器公网 IP。
2. **SSH**：服务器 IP、登录用户（如 `root` 或 `ubuntu`），以及按 §9 放好公钥。

> 注：`www.example.com` 与 `example.com` 现有服务保持在原 server 块里，新配置只新增一个 `data.` 的 server 块，不动旧配置。
